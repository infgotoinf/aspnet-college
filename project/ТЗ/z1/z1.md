## 1. Согласование темы

**Тема проекта:** веб-мессенджер на ASP.NET Core Razor Pages с личными и групповыми чатами. Пользователи могут вести переписку, управлять контактами и получать уведомления о новых сообщениях и прочтении. Доступ к чатам проверяется на сервере: читать переписку и отправлять сообщения могут только участники чата.

**Страницы:**
- Главная (`/`)
- Список чатов (`/chats`)
- Просмотр чата (`/chats/{id}`)
- Создание чата (`/chats/new`)
- Контакты и профиль (`/contacts`, `/profile`)
- Регистрация и вход (`/account/register`, `/account/login`)
- Админ-панель (`/admin`)

**Сущности:** пользователь и роль Identity, `Conversation` (чат), `ConversationMember` (участник чата), `Message` (сообщение), `MessageRead` (отметка прочтения), `Contact` (контакт).

**SignalR-события:** новое сообщение в чате и отметка прочтения. Клиент получает события только для чатов, участником которых является.

**Роли:** `User` — обычный пользователь; `Admin` — администратор с доступом к админ-панели и данным всех пользователей.

## 2. Проектирование

### Схема базы данных

- **Пользователи и роли:** стандартные таблицы ASP.NET Core Identity; пользовательские данные расширяются при необходимости.
- **Conversation:** идентификатор, название, тип чата, дата создания; имеет участников и сообщения.
- **ConversationMember:** составной ключ `(ConversationId, UserId)`; связывает чаты и пользователей отношением многие-ко-многим.
- **Message:** идентификатор, `ConversationId`, автор (`UserId`), текст, время отправки; принадлежит чату и имеет отметки прочтения.
- **MessageRead:** составной ключ `(MessageId, UserId)`, время прочтения; связывает сообщение с пользователем.
- **Contact:** составной ключ `(OwnerId, ContactUserId)`; связывает пользователя с контактом.

Удаление чата каскадно удаляет его участников и сообщения, а удаление сообщения — связанные отметки прочтения. Предусмотрены индексы для поиска сообщений по чату и сортировки по времени, а также для поиска чатов пользователя.

### API

Все маршруты API находятся под `/api/v1` и `/api/v2` и защищены JWT, кроме входа. Контракты версий различаются: например, v1 возвращает краткие данные чата и сообщения, v2 — те же данные с пагинацией и дополнительными метаданными.

- `POST /api/auth/login` — вход и получение JWT.
- `GET /api/v1/conversations` — список доступных пользователю чатов.
- `GET /api/v1/conversations/{id}` — получение чата.
- `POST /api/v1/conversations` — создание чата.
- `PUT /api/v1/conversations/{id}` — изменение чата.
- `DELETE /api/v1/conversations/{id}` — удаление чата.
- Для v2 — соответствующие CRUD-маршруты с отличающимся DTO, включая пагинацию списка и сообщений.

Операции с чатами ограничены членством пользователя; администратор может работать со всеми чатами. API использует DTO, а не EF-сущности.

### Политики и доступ

- `AdminOnly` — доступ к админ-панели только для роли `Admin`.
- `ResourceOwner` — доступ к ресурсу его владельцу; администратор также получает доступ.
- Проверка участника чата выполняется отдельно на сервере для просмотра, отправки сообщения и отметки прочтения. Идентификатор пользователя берётся из claims, а не из данных, присланных браузером.
